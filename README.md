# Static AI Leadbot

Встраиваемый русскоязычный AI-чат для обычных статических сайтов с отдельной формой лида и отправкой заявки в Telegram.

- Виджет подключается одним `<script>` и изолирован через Shadow DOM.
- AI-ключ и Telegram-токен находятся только на backend.
- В Telegram отправляются **только явно заполненные поля формы**, а не история чата.
- Отправка лида подтверждается только после успешного ответа Telegram Bot API.
- Есть CORS allowlist, проверки данных, honeypot, лимиты по IP, защита от дублей, тайм-ауты и ограничение размера запросов.

> GitHub Pages может разместить статический сайт, но не запускает `server.js`. Backend нужно развернуть на Node.js-хостинге/VPS.

## Структура

```text
public/
  demo.html       демонстрационная статическая страница
  widget.js       встраиваемый виджет
examples/
  embed.html      фрагмент подключения
server.js         API чата, заявок и раздача демо
package.json
test/server.test.js
Dockerfile
.env.example
```

## Быстрый запуск

Требуется Node.js 22 или новее.

```bash
cp .env.example .env
# заполните .env
npm run dev
```

Откройте `http://localhost:3000/demo.html`. Команда `npm run dev` читает `.env`; `npm start` ожидает переменные окружения от хостинга.

Проверки:

```bash
npm run check
npm test
```

В проекте нет внешних npm-зависимостей, поэтому `npm install` не обязателен.

## Настройка Telegram

1. Создайте бота через официального `@BotFather` и получите токен.
2. Напишите вашему боту сообщение или добавьте его в нужную группу.
3. Узнайте `chat_id` через Telegram Bot API либо своего бота/служебный скрипт.
4. На хостинге задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
5. Не помещайте токен в HTML, `widget.js`, README или GitHub Secrets с выводом в клиентскую сборку.

Для темы форума Telegram можно задать `TELEGRAM_MESSAGE_THREAD_ID`.

## Настройка AI

По умолчанию используется OpenAI-совместимый endpoint:

```env
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-4o-mini
OPENAI_API_KEY=...
```

Можно изменить endpoint и модель, если сервис поддерживает формат `/chat/completions`. Доступность модели и допустимые параметры необходимо проверить у выбранного провайдера.

Бот не имеет собственной базы знаний. Текст `AI_SYSTEM_PROMPT` задаёт его роль, но не превращает ответы в проверенные сведения.

## Переменные окружения

Скопируйте `.env.example` в `.env`. Основные поля:

| Переменная | Назначение |
|---|---|
| `PUBLIC_ORIGIN` | HTTPS-адрес backend после развёртывания |
| `ALLOWED_ORIGINS` | Домены сайтов с виджетом через запятую, без путей |
| `OPENAI_API_KEY` | секрет AI-провайдера |
| `TELEGRAM_BOT_TOKEN` | секрет Telegram-бота |
| `TELEGRAM_CHAT_ID` | получатель заявки |
| `COMPANY_NAME` | название в уведомлении и демо |
| `PRIVACY_URL` | HTTPS-ссылка на политику |
| `CONTACT_URL` | HTTPS-ссылка для связи |
| `TRUST_PROXY_HOPS` | число доверенных reverse proxy; настраивать по документации хостинга |

`ALLOWED_ORIGINS` указывайте строго:

```env
PUBLIC_ORIGIN=https://bot.example.com
ALLOWED_ORIGINS=https://example.com,https://www.example.com
```

Origin включает схему и порт, но не путь. CORS ограничивает браузеры, однако не является аутентификацией и не блокирует прямые автоматизированные запросы.

## Встраивание в статический сайт

Сначала разверните backend по HTTPS. Затем перед `</body>` сайта вставьте:

```html
<script
  src="https://bot.example.com/widget.js"
  data-api-base="https://bot.example.com"
  data-title="Помощник компании"
  data-accent="#2457d6"
  defer
></script>
```

Адрес в `src` и `data-api-base` замените на адрес backend. Фрагмент размещайте один раз. Домен статического сайта добавьте в `ALLOWED_ORIGINS`.

Дополнительные атрибуты:

- `data-title` — заголовок;
- `data-accent` — цвет в формате `#RRGGBB`;
- `data-position="left"` — расположение слева;
- `data-greeting` — приветствие;
- `data-cta` — подпись кнопки формы заявки.

## API

- `POST /api/chat` — сообщения AI;
- `POST /api/leads` — отправка заполненной формы в Telegram;
- `GET /api/config` — публичная конфигурация;
- `GET /healthz` — healthcheck;
- `GET /widget.js` — файл виджета.

Форма отправляет: имя, контакт, комментарий, URL страницы и UTM-метки. История чата в payload заявки не добавляется и backend её не принимает.

## Развёртывание

На Node.js-хостинге:

```text
Build command:  (пусто либо npm run check)
Start command:  npm start
Health path:    /healthz
```

Или Docker:

```bash
docker build -t static-ai-leadbot .
docker run --env-file .env -p 3000:3000 static-ai-leadbot
```

После запуска проверьте:

1. `/healthz` возвращает `{"status":"ok"}`.
2. Демо открывается, чат отвечает.
3. Тестовая заявка действительно приходит в правильный Telegram-чат.
4. Повторная заявка отклоняется как дубликат.
5. Запрос с постороннего Origin получает 403.
6. В репозитории и DevTools браузера нет секретов.

## Ограничения и эксплуатация

- Rate limit и дедупликация находятся в памяти одного процесса. Для нескольких экземпляров нужен общий storage (например, Redis) и внешний rate limiter.
- Не считайте CORS защитой от ботов. Для большого трафика добавьте серверно проверяемую CAPTCHA/WAF и жёсткий бюджет AI.
- Перед публичным запуском настройте HTTPS, мониторинг, резервный канал для лидов и ограничения расходов.
- Укажите настоящую политику обработки данных и получите требуемое применимым правом согласие. Не просите пользователей отправлять чувствительные сведения.
- Проект не хранит заявки в базе: при недоступности Telegram клиент увидит ошибку и сможет повторить отправку.

## Секреты

`.env` исключён через `.gitignore`. Если токен всё же попал в Git, немедленно отзовите его и выпустите новый: удаления файла недостаточно, секрет останется в истории.
